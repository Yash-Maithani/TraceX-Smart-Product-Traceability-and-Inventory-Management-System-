2. Record D-22 (Resolved, owner-delegated to the planner) for the trace token design:
   - traceToken is opaque: 16 random bytes (SecureRandom) as the nonce, plus a 16-byte tag from HMAC-SHA256(TRACE_TOKEN_SECRET, nonce), both base64url, joined with a dot. It contains no batch id, no batchCode and no date.
   - It is stored on the batch in field traceToken with a unique sparse index. A token is resolved by verifying the tag in constant time first (reject without a database read if invalid), then an exact lookup on the stored value.
   - A token never changes for the life of a batch. Archiving a batch makes its public link return 404, and restoring it makes the link work again with the same token. Dispatched batches stay publicly traceable and show status DISPATCHED.
   - TRACE_TOKEN_SECRET must be stable. Rotating it invalidates every printed QR code. Document this in docs/deployment-runbook.md.
   - SPEC section 8.1 currently says TRACE_TOKEN_SECRET falls back to JWT_SECRET. Change this: dev, test and e2e may fall back, but the prod profile fails fast at startup naming TRACE_TOKEN_SECRET when it is missing or shorter than 32 characters.
